# Roadmap and status

What has shipped, in order, and what is next. Each shipped line links to its evidence.

## Shipped

- **v0 (June 2026).** Generator, MCP harness, one core task suite, the scorer, a runnable quickstart.
- **v0.2, the builder release.** Credential-free proof path, pinned First Contact receipt, current MCP comparison, the raw-data-free transfer analyzer (now under `research/transfer/`, ADR-0013).
- **First Contact.** The first cross-graded measurement: Claude Sonnet 4.6 on the 4-question starter suite, k=3, GPT-4o as the independent grader. pass^3 75%, provenance 100%, accuracy 100%. The missing question is the unresolvable tie; the model manufactured a tiebreaker in 3 runs of 3. Report with per-epoch transcripts: [`examples/first-contact-report.md`](../examples/first-contact-report.md).
- **Scorer hardening.** Parametric k (any k >= 1), committed-answer accuracy (det-2), committed-answer refusal (det-3), per-field provenance read from the agent's tool traffic (det-4). Decisions on record in [`adr/`](adr/).
- **meridian and the leaderboard** (ADR-0006, ADR-0011). 22 questions, at least five per conflict kind, both resolution rules, anti-prior values, gated by adversarial review and live baselines. The first five-model run: Sonnet 4.6 86.4%, GPT-4o 45.5% (it skips the CRM leg of cross-silo joins), and every model fabricated tie-breaks on the unresolvable column. The 2026-07-06 rows changed that: claude-fable-5 and claude-opus-4-8 are the first to hold the column at 100%. Eight single-model rows plus a MoA ensemble ranked together, with a `harness` column disclosing how each row was run; the ensemble lands at #4, below opus-4.8 alone, so the advisory sub-models added noise without adding reliability. Table: [`leaderboard.md`](leaderboard.md).
- **The technical report.** [`report.md`](report.md): the benchmark and the protocol as the contribution, the leaderboard, delegation and scaffold measurements as the evidence.
- **Scenario factory and holdout protocol** (ADR-0008). `python -m tessera.factory.export --seed N` re-deals meridian's conflict graph per seed and synthesizes fresh anti-prior values with the category counts fixed; seed 0 equals the authored meridian object for object, so the published baseline stays valid. A leaderboard's headline numbers can run on a withheld seed fixed in advance by a salted SHA-256 commitment and revealed afterwards as `{seed, salt, factory_version}`, so anyone can recompute the digest and rebuild the exact organisation. The factory automates case production, never the standard, the adversarial design or the risk calibration.
- **Reliability under delegation** (ADR-0007, [`delegation.md`](delegation.md)). A producer researches, a tool-less consumer commits. The hop is a faithful conduit: it dropped 0 of 27 producer refusals, all 12 on the unresolvable ties included, and challenged 0 of 3 fabrications (one explicitly rationalized).
- **The refusal-aware scaffold** (ADR-0009, [`scaffold.md`](scaffold.md)). Two prompts differing in exactly one block, `--scaffold baseline` against `--scaffold refusal_aware`, five factory instances, paired McNemar. It converts tie detection into refusal without an answering loss for models that already detect the conflict (Sonnet 4.6 20% to 88% on the unresolvable column, GPT-4o 16% to 48%; refusal-subset McNemar p = 0.0001 and p = 0.004) and cannot manufacture the detection a weaker model lacks (haiku pays for the gain in over-refusal; gpt-4o-mini never reaches the tie). Confirmed on a withheld holdout seed.
- **v0.3 (2026-09-02).** One `tessera` command, one home (`~/.tessera`), one payload shared by the CLI, the API and the app; runs as folders; the app rebuilt around a sentence form, a report page and a suite sheet; the package is `tessera-eval` with the UI inside the wheel. Record: [ADR-0014](adr/0014-one-cli-one-home-one-payload.md) and the [CHANGELOG](../CHANGELOG.md).

## Next

- **Backed leaderboard rows.** Every row in `leaderboard.rows.json` currently has `log: null`. Backing a row means re-running that model on meridian with a key and committing the `.eval`; `tessera leaderboard verify` then checks the row against it. A row that does not reproduce stays `null`.
- **Live holdout leaderboard, your-own-data generation.** A published row produced on a withheld seed with `factory_version` stamped on it and the seed exposed in the API and the app (the ADR-0008 non-goals), and the generator pointed at knowledge beyond the meridian family.
- **Delegation, deeper.** Weaker consumers, tool-using consumers, longer chains.
- **Synthetic-to-real validation (Q4 2026).** Freeze one model and harness panel across Tessera and an authorized production eval, register it with a signed public tag and OSF, then publish the rank-transfer result even if it is negative or inconclusive. The public [draft](validation-preregistration.md) blocks runs until its panel and hashes are frozen.
